# AI エージェントで MSX プログラムをデバッグする

[English version](README.md)

blueMSX+ には MCP サーバー `bluemsx-mcp.exe` が同梱されています。
これを利用することで、Claude Code などの AI エージェントに blueMSX+ がエミュレートする MSX の内部調査や操作を行わせることができます。
実現したい内容を言葉で伝えるだけで、エージェントがマシンの起動や操作、メモリの読み取り、ブレークポイントの設定、キー入力、結果の報告などを自律的に行います。

エージェントが接続できるのは、blueMSX+ のメニューまたは起動時のオプションから許可した時のみです。
また、エージェントが行った操作内容はすべて blueMSX+ 上で確認できます。

# 利用者向け説明

## エージェントに依頼できること

エージェントへの指示と、それに対するエージェントの動作の例を以下に示します。

| 指示の例 | エージェントの動作 |
|---|---|
| 「ボスが出るとゲームが固まる。どこで止まっている?」 | マシンを一時停止し、レジスタとスタックを読み取り、プログラムカウンタ付近を逆アセンブルします。 |
| 「残機数が入っている変数を探して」 | メモリ全体から値を探し、残機が減るたびに候補を絞り込みます。 |
| 「スプライトテーブルが何かに上書きされる。犯人は?」 | VRAM の該当範囲にウォッチポイントを設定し、書き込まれた時点で停止させて、そのときの実行位置と呼び出し元を報告します。 |
| 「バンク 5 の DRAW_ENEMY のコードを見せて」 | そのバンクが現在切り替わっていなくても、シンボル付きで逆アセンブルします。 |
| 「バンク 3 の 0x6000 のルーチンが動いたら止めて」 | バンク 3 が切り替わっているときのみ有効なブレークポイントを置きます。 |
| 「このルーチンのバンク 7 版を一度動かして」 | バンク 7 を CPU から見える位置に切り替えてステップ実行し、プログラムが選択していたバンクを知らせ、元に戻せるようにします。 |
| 「残機を 99 にして」「そのチェックを飛ばして」 | メモリまたは CPU レジスタを書き換えます。RAM と VRAM への書き込みは取り消せます。 |
| 「RUN と打って、画面に何が出たか教えて」 | キー入力を行い、画面をテキストとして読み取ります。グラフィックモードの場合は PNG ファイルに保存します。 |
| 「ROM を作り直したので、もう一度動かして」 | マシンのハードリセットを行い、新しい ROM ファイルを読み込ませます。 |
| 「この場面を覚えておいて。ボス戦をやり直したい」 | マシンのスナップショットを取得し、いつでもその状態へ巻き戻せるようにします。 |

メガ ROM については、CPU から見えていないバンクであっても読み出し、逆アセンブル、ブレークポイントの設定が可能です。
バンク番号を記録したシンボルファイルが存在すれば、バンクごとに正しいシンボルが適用されます。
対応するマッパーについては「制限と注意点」の節を参照してください。
なお、エージェントの応答では「バンク」を「セグメント」と表現する場合があります。

## 必要なもの

- blueMSX+ 本体 (blueMSX+.exe)
- `bluemsx-mcp.exe` および本ドキュメント `bluemsx-mcp.ja.md` (blueMSX+ の `Tools` フォルダに格納されています)
- MCP クライアント(Claude Code など、MCP サーバーに対応したプログラム)

## 設定

### 1. MCP クライアントにサーバーを登録する

登録作業自体をエージェントに任せることができます。
本ドキュメントのパス(例: `C:\blueMSX+\Tools\bluemsx-mcp.ja.md`)を伝え、サーバーの登録を依頼してください。
Claude Code の場合、登録後のセッションから直ちにツールが利用可能になります。

手動で登録する場合は、以下のコマンドを実行します。

Claude Code の場合:

```
claude mcp add --scope user bluemsx -- "C:\blueMSX+\Tools\bluemsx-mcp.exe"
```

同じ名前のサーバーが既に登録されている場合、登録は失敗します。
事前に `claude mcp remove --scope user bluemsx` で削除するか、別の名前を指定してください。

他のクライアントの場合は、`bluemsx-mcp.exe` を引数なしでローカルコマンド(stdio)サーバーとして登録します。

```json
{
  "mcpServers": {
    "bluemsx": { "command": "C:\\blueMSX+\\Tools\\bluemsx-mcp.exe" }
  }
}
```

上記の例はいずれも、blueMSX+ を `C:\blueMSX+` に配置した場合のものです。
インストール先が異なる場合はパスを適宜書き換えてください。

### 2. 許可の確認

事前に許可を与えていない場合、エージェントが以下の操作を行う前に Claude Code が確認を求めます。

- 本 MCP サーバーのツールを使用するとき。一括して許可するには、Claude Code の設定ファイルの `permissions.allow` に `"mcp__bluemsx"`(サーバーを登録した名前)を追加します。
- blueMSX+ を起動するとき。シェルコマンド扱いとなるため、他のコマンド実行時と同様に確認プロンプトが表示されます。
- スクリーンショットを撮影・取得するとき。パスを指定しない場合、スクリーンショットは `%LOCALAPPDATA%\blueMSXplus\agent` に保存されます。

他のクライアントを使用している場合は、それぞれのクライアントが定める手順に従ってツールの許可を行ってください。

### 3. エージェントからエミュレータへの接続方法

#### 新規にエミュレータを起動させる

開発時の一般的な方法です。
エージェントに blueMSX+ の起動、プログラムのロード、デバッグを行わせ、作業完了後に終了させます。
「`game.rom` を MSX2 で起動して、ボスで固まる原因を調べて」のように指示すると、エージェントは次のようなコマンドを実行して blueMSX+ を起動します。

```
"C:\blueMSX+\blueMSX+.exe" --machine "MSX2 - C-BIOS" --rom1 "C:\dev\game\game.rom" --agentcontrol full
```

`--agentcontrol full`(または `read`)による権限付与はその回の起動にのみ適用され、ユーザーの普段使い用の設定には影響を与えません。

ウィンドウを開かずに起動させることもできます(`--hidden` オプション)。
エミュレータが終了されずに動き続けてしまっている場合は、`taskkill` コマンドで終了させてください。
(詳細については、「うまくいかないとき」の節を参照してください)。

#### 動作中のエミュレータに接続させる

ゲームのプレイ中やテスト中に問題が発生し、エミュレータを再起動することなく現在の状態のまま調査させたい場合の方法です。
**ツール → エージェント制御** からエージェントの接続を許可してください。

| 接続設定 | エージェントができること |
|---|---|
| **許可しない** | 何もできません。接続はすべて拒否されます(初期設定)。 |
| **読み取りのみ** | マシンを一時停止しての内部状態の参照(メモリ、レジスタ、スロット構成、バンク、画面)、メモリ上の値の検索、シンボルファイルの読み込みなど。一時停止後の再開はメニューの **実行 → 実行** から行ってください。 |
| **書き込みも許可** | すべての操作 |

メニューから行った設定は保存され次回の起動時にも引き継がれます。
ただし、`--agentcontrol` オプションを付けて起動したセッションでは保存されません。
権限レベルを下げた場合は即座に反映され、「許可しない」にした場合は接続中のエージェントも切断されます。

「読み取りのみ」または「書き込みも許可」の有効中は、ウィンドウを最小化しても画面描画が継続されます。

### 4. 利用する

blueMSX+ を起動してプログラムをロードし(エージェントに任せても構いません)、エージェントに指示を出します。
MCP サーバー(エージェントが起動する)と blueMSX+ はどちらを先に起動しても構いません。
サーバーは、エージェントが最初にツールを使用したタイミングで blueMSX+ に接続し、blueMSX+ を再起動した場合でも自動的に再接続を行います。

処理の途中でエージェントとのセッションを中断あるいは終了した場合、エミュレータ側でもそれに伴う処理がキャンセルされます。

エージェントによって設定されたブレークポイントでは、手動で操作している最中であってもマシンが停止します。
通常はセッション終了とともに自動解除されますが、バンク指定のブレークポイントやウォッチポイントは、明示的に解除されるまで解除されません。
エージェントが設定したブレークポイントとウォッチポイントは、いずれもデバッガのウィンドウには表示されません。

接続を受け付けているエミュレータが複数存在し、常に特定のインスタンスを対象にしたい場合は、マシン名を指定してサーバーを登録します。

```
claude mcp add --scope user bluemsx-fdd -- "C:\blueMSX+\Tools\bluemsx-mcp.exe" --instance "MSX2 - C-BIOS FDD"
```

## エージェントの操作を確認する

**ツール → エージェント制御 → エージェントの操作履歴...** を選択すると、エージェントがマシンに対して行った操作の一覧ウィンドウが表示されます。
以下に表示例を示します。

```
127.0.0.1:53093 で待ち受け中     権限: 書き込みも許可
接続中: mcp #1

時刻          クライアント  操作                対象                                            結果
09:24:44.120  mcp #1        接続
09:24:44.310  mcp #1        シンボル読み込み    game.sld  (C:\dev\game)
09:24:45.002  mcp #1        一時停止
09:24:45.100  mcp #1        読み取り x8         slot3.2:seg0+0x0000-0x001F (Z80 0xC000-0xC01F)
09:24:45.420  mcp #1        書き込み            slot3.2:seg0+0x0010 (Z80 0xC010)                変更前 FF 変更後 63
09:24:45.600  mcp #1        書き込みの取り消し  slot3.2:seg0+0x0010 (Z80 0xC010)                変更前 63 変更後 FF
09:24:45.700  mcp #1        書き込み            slot1.0:seg0+0x0010 (Z80 0x4010)                反映されず (31 のまま)
09:24:45.810  mcp #1        バンク切り替え      slot1.0 (Z80 0x6000-0x7FFF)                     seg0 -> seg3
09:24:45.900  mcp #1        ブレーク設定        slot1.0:seg3+0x0000 (Z80 0x6000)
09:24:46.020  mcp #1        キーを押して離す    space
```

1 行目は接続待ち受け状態と現在の権限を表し、接続元は同一 PC 内のプログラムに限定されます。
2 行目は接続中のツール名と識別番号です(`mcp #1` は本サーバーの 1 本目の接続)。
名前の後ろに「(遮断中)」とある場合は、エージェント制御が「許可しない」に変更されたことを示しており、該当ツールの操作は直ちに無効化され接続も間もなく切断されます。
古い履歴が破棄された場合は、その行数が 3 行目に表示されます。

その下には、実行された操作が古い順に 1 行ずつリストアップされます。

| 列 | 意味 |
|---|---|
| 時刻 | 操作の時刻。ミリ秒まで表示されます。 |
| クライアント | どの接続による操作か。 |
| 操作 | 実行した操作内容。`x8` は同一のメモリ読み取りや失敗が 8 回連続したものを 1 行に集約した表記です。 |
| 対象 | 操作のターゲット。`slot3.2:seg0+0x0010 (Z80 0xC010)` は、スロット 3.2 の RAM のセグメント 0 のうち、現在 Z80 から 0xC010 として見えている位置を示します。 |
| 結果 | 操作の結果。書き込み前後の値(後の値は書き込み直後にメモリから再読込したもの)、レジスタの変更前後の値、値の検索で見つかった候補数、拒否理由など。「失敗(エミュレーター停止中)」は、要求された操作が実行されなかった旨と、その理由を表します。 |

拒否された操作、失敗した操作、およびメモリに反映されなかった書き込みは、行全体がオレンジ色でハイライトされます。

なお、エージェントが参照したすべての情報がこのログに載るわけではなく、レジスタ、スロット、VDP の読み取り操作は履歴に表示されません。

ウィンドウ上では、Ctrl キーを押しながら `+` または `-` で文字サイズを変更できます。
`Ctrl + 0` で初期サイズに戻ります。

## 作成されるファイル

エージェント制御の機能が作成するファイルは以下の通りです。
いずれも `%LOCALAPPDATA%\blueMSXplus\agent` フォルダに作成され、blueMSX+ のフォルダには作成されません。

| ファイル | 内容 | 作成と削除 |
|---|---|---|
| `instance-<pid>.json` | エージェントが接続するためのポート番号とトークン、権限、マシン名。`<pid>` は blueMSX+ のプロセス ID です。 | エージェント制御が「読み取りのみ」または「書き込みも許可」のときに作成され、「許可しない」にしたときと blueMSX+ の終了時に削除されます。強制終了で削除されなかったファイルは、後で blueMSX+ または MCP サーバーが削除します。 |
| `screen-<pid>.png` | パスを指定せずに取得したスクリーンショット。 | 取得のたびに上書きされます。自動では削除されません。 |

エージェントがパスを指定してスクリーンショットを保存した場合は、そのパスに作成されます(「書き込みも許可」のときのみ)。
スナップショットと操作履歴はメモリ上にのみ保持され、ファイルには保存されません。
MCP サーバー `bluemsx-mcp.exe` はファイルを作成しません。

## シンボルファイルを渡す

シンボルファイルを読み込むと、エージェントは逆アセンブルやスタック表示にそのシンボルを利用できるようになり、「`DRAW_ENEMY` で止めて」のようにシンボル名で位置を指定できるようになります。
読み込ませたいシンボルファイルのパスをエージェントに伝えてください(例: 「`C:\dev\game\game.sld` を読み込んで」)。

| ツール | 渡すファイル | バンク番号 |
|---|---|---|
| sjasmplus | `--sld` の出力(`.sld`) | あり(デバイスのページから求めます) |
| sjasmplus | `--sym` の出力 | なし |
| asMSX | `.sym` | あり |
| WLA-DX | `wlalink -S` のシンボルファイル | あり |
| SDCC と、それを使用するライブラリ(MSXgl、Fusion-C、libmsx など) | `.noi` またはリンカの `.map` | 64 kB より上にリンクしたコードはあり(例: `-Wl-b_SEG5=0x58000` はバンク 5) |
| pasmo、Glass、tniASM | `名前 EQU 値` 形式のシンボルファイル | なし |
| z88dk | `.map` | なし |

ドライブ名から始まる絶対パスで指定してください。
複数のファイルを同時に読み込むことも可能です。
フォルダと拡張子を除いたファイル名が読み込み済みのものと一致する場合は、新しくロードした内容で置き換えます。

「バンク番号」はメガ ROM の場合に意味を持ちます。
バンク番号があれば、各シンボルがそれぞれのバンクに正確に紐付くため、異なるバンク内の同アドレスであっても正しいシンボルが反映されます。
バンク番号がない場合は、その時点で切り替わっているバンク内の該当アドレスにのみシンボルが紐付けられます。

バンク番号が含まれるファイルは、対応するカートリッジに紐付ける必要があります。
ROM ファイルと名前が一致していれば、自動的に紐付けられます(例: `game.rom` と `game.sld`)。
一致しない場合、エージェントが候補のスロットを提示してどれにするかを確認してきます。
回答するまでそのファイルのシンボルは有効になりません。
RAM 上で動作するプログラム(ディスクからロードするものなど)では必ずこの確認が発生し、回答にはメモリマッパーのスロットを指定します。
なお、ディスク用プログラムの場合、DOS が別のセグメントを割り当てることでシンボルがずれることがあります。

## 制限と注意点(マッパー、フラッシュ、できないこと)

- バンク関連の機能(未選択バンクの読み出し・逆アセンブル、バンク指定のブレークポイント、バンク番号付きシンボルファイルの紐付け、スタック表示でのバンク名表示)がサポートされるマッパーは以下の通りです:
  - メモリマッパー
  - ASCII 8、ASCII 16、ASCII 8(SRAM)、ASCII 16(SRAM)
  - Konami、Konami SCC、Konami Generic
  - SCC、SCC-I、The Snatcher、SD Snatcher、SCC mirrored、SCC extended
  - ASCII16-X、Yamanooto、NEO-8、NEO-16
  - Mega Flash Rom SCC、Mega Flash Rom SCC+
  - Manbow 2、Manbow 2 v2
  - Super Pierrot、Hamaraja Night、Standard
- このうち、ASCII 8、ASCII 16(SRAM 付き含む)、Konami、Konami SCC、Konami Generic、ASCII16-X、Yamanooto、NEO-8、NEO-16、Super Pierrot では、エージェント側からバンクを切り替えることも可能です。
- 上記以外のカートリッジでは、エージェントから参照できるのはその時点で CPU から見えている内容のみとなります。
- エミュレータが ROM に対してどのマッパーを選択したかは、エージェントに問い合わせることで確認できます(スロットごとのマッパー名が表示されます)。もし誤っている場合は、`--romtype1` オプションで正しいマッパーを指定して起動し直してください(指定可能なマッパー名の一覧は `blueMSX+.exe --listromtypes` で確認できます)。
- メモリ上の値の検索は RAM および VRAM に対して行えます。検索ステップの合間にはマシンを動作させる必要があり、「読み取りのみ」モードの場合はユーザー自身が再開操作を行う必要があります。
- フラッシュカートリッジ(ASCII16-X、Yamanooto、Flash-ROM SCC、Mega Flash Rom SCC 系)は、MSX が書き込んだ内容を blueMSX+ の `SRAM` フォルダ内に ROM と同名のファイル(`game.flash` または `game.sram`)として保存し、次回起動時にそれを読み込みます。この仕様のため、作り直した ROM がそのまま動作するとは限らない点に注意してください。エージェントがこのファイルの存在を認識するのはリセット時のみであり、新しくエミュレータを起動した時点では認識されません。作り直した ROM をテストする前に、該当する SRAM/Flash ファイルを削除して(削除させて)ください。
- スナップショット機能で復元できるのはマシン状態のみです。ディスク、テープ、大半のカートリッジの SRAM やフラッシュの内容は復元されません。
- キーボードの入力は、マシンが稼働中でキーボード入力を受け付け可能な状態にあるときのみ機能します。日本語配列および国際配列のマシンで利用できます。その他の配列(ドイツ語、フランス語、ロシア語など)であっても、キー名による入力は可能です。長文を入力する場合は、何度かに分けて送信されます。

エージェントにできないことと、その代わりにすること:

| できないこと | 代わりにすること |
|---|---|
| 動作中のカートリッジ、ディスク、テープの差し替え | 同じ名前で作り直したファイルであれば、ハードリセットで再読み込みします。別のファイルやマッパーの種類にする場合は、エミュレータを起動し直します(`--rom1`、`--romtype1`、`--diskA`)。 |
| 動作中のマシンの変更 | `--machine` を指定してエミュレータを起動し直します。 |
| ステートのファイルへの保存と読み込み | スナップショットにより 1 つの状態をメモリに保持できます。ステートファイルから始める場合は、起動時に `--state` を指定します。 |
| エミュレーション速度の変更 | 起動時に `--speed` を指定します。 |
| 操作の記録と再生 | できません。 |
| フレーム数を指定した実行 | 時間を決めて停止を待つか、命令数を指定してステップ実行します。 |
| 条件付きブレークポイントやヒットカウント | ウォッチポイントであれば、書き込まれた値が条件に合うときのみ停止させることが可能です。 |
| メモリ、VRAM、ポートの読み出しでの停止 | ウォッチポイントで停止するのは書き込みと OUT のみです。 |
| 切り替わっていないバンクのウォッチポイント | そのバンクにブレークポイントを設定します。 |
| I/O ポートへの書き込み | できません。 |
| VDP に書き込まれた内容、パレット、スプライトの解読 | VDP のレジスタとスクリーンショットを読み取ります。 |
| BASIC のリスト表示、BASIC の行での停止、BASIC の変数の読み出し | `LIST` と入力して画面を読み取り、メモリを読み取ります(BASIC を搭載したマシンの場合)。 |
| アセンブラのリスト(`.lst`)からのシンボルの取得 | シンボルファイル(`.sld`、`.sym`、`.noi`、`.map`)を渡してください。 |
| トレース、プロファイル、カバレッジの計測、メモリへの直接アセンブル、DAP デバッガとしての動作、グラフィカルなビューアの表示 | できません。 |

## うまくいかないとき

| 症状 | 対処法 |
|---|---|
| 接続を受け付けているエミュレータがないとエージェントに言われる。 | blueMSX+ を起動し、**ツール → エージェント制御** から「読み取りのみ」または「書き込みも許可」を選択するか、エージェントに起動を指示してください。 |
| 別のセッションがすでに接続していると言われる。 | 該当する古いセッション(閉じ忘れた前のセッションなど)を終了するか、別のエミュレータを起動します。 |
| 接続を受け付けているエミュレータが 2 つあると言われる。 | 不要な方を閉じるか、そちらのエージェント制御を「許可しない」に変更してください。 |
| エミュレータのウィンドウが応答しない(ダイアログ等が開いている)と言われる。 | エミュレータ側で開いているメニュー、ダイアログ、ディスク確認プロンプトなどを閉じてから、エージェントに再試行させてください。 |
| 「読み取りのみ」モードで、エージェントの参照後にゲームが停止したままになる。 | 「読み取りのみ」モードではエージェント側から再開できないため、メニューの **実行 → 実行** を選択してください。 |
| エージェントの動作をすぐに止めたい。 | エージェント制御を「許可しない」に切り替えると、エージェントは即座に切断されます。なお、バンク指定のブレークポイントやウォッチポイントはそのまま残ります。 |
| 「許可しない」にした後、「読み取りのみ」や「書き込みも許可」に戻せない。 | 前の要求がまだ処理中です。少し待ってから再度選択してください。 |
| セッションが終了したのに、まだマシンが停止する。 | 新しいセッションでエージェントにブレークポイントとウォッチポイントの解除を依頼するか、blueMSX+ を起動し直してください。 |
| エージェントがウィンドウ非表示で起動したエミュレータが動作し続けている。 | `taskkill /PID <pid>` を `/F` なしで実行してください(タスクマネージャーや `/F` で終了させると SRAM が保存されません)。pid は `%LOCALAPPDATA%\blueMSXplus\agent\instance-<pid>.json` のファイル名から確認できます。 |
| 作り直したフラッシュカートリッジの ROM が反映されない。 | マシンが動作していない状態で blueMSX+ の `SRAM` フォルダ内の `<rom>.flash` または `<rom>.sram` を削除してから、起動し直してください。 |
| エミュレータにエラーが表示されているのに、エージェントが何も言わない。 | エージェントからはエミュレータ自身のメッセージが見えません。ウィンドウに表示されている内容を伝えてください。 |

# エージェント向け説明

ここから先は AI エージェント向けの参考情報です。
エージェントは `bmsx_reference <topic>` コマンドにより任意の節を参照できます(参照可能なのは英語版です)。
MCP サーバーを利用するだけであれば、ユーザーが熟読する必要はありません。

各ツールの引数、選択可能な値、既定値は、接続時にツール一覧と一緒にエージェントへ渡されます。
ここでは、そこに収まらない内容を補います。

セッションの初めに `bmsx_break op=list` と `bmsx_watch op=list` を呼び出すと、前のクライアントが残したブレークポイントとウォッチポイントを確認できます。
セグメントのブレークポイントとウォッチポイントは、セッションの終了、エージェント制御の「許可しない」、新しいセッションのいずれでも解除されず、そのことは通知されません。

## 一時停止中と実行中: いつ何が使用可能か

マシン内部を調査できるのは一時停止中のみです。
メモリ、レジスタ、スタック、逆アセンブル、バンク一覧、値の検索、画面テキストの読み取りには一時停止が必須となります。
メモリ・レジスタの書き換え、取り消し、バンク切り替え、スナップショットの取得も同様です。
実行中のマシンに対してこれらを実行した場合、`not_paused` エラーが返されます。
エージェント側の意図しないタイミングで勝手にマシンが停止させられることはありません。
なお、引数の不正については、停止状態のチェックよりも前に検証され報告されます。

マシンを一時停止させる方法:

- `bmsx_run how=pause` を実行する。「読み取りのみ」モードでも使用可能ですが、その場合の再開はユーザー操作となります。「読み取りのみ」では再開、ステップ実行、`run_until` は使用できません。
- `bmsx_run_until` で、ブレークポイントまたはウォッチポイントで停止するまで待つ。
- `bmsx_run_until timeout_ms=N pause_at_timeout=true` を実行する。時間切れで一時停止します。実行中のプログラムを定期的に確認するには、読み取った後に再びこれを呼び出します。

マシンの実行中も使用可能なもの: `bmsx_status`(状態、ページインしているセグメント、マシン名、実行したフレーム数。レジスタ、CPU、VDP は含まない)、`bmsx_slots`(切り替えたバンクの `*` 印は付かない)、`vram:` アドレスと、終わりより後ろのセグメントに対する `bmsx_mem_resolve`、ブレークポイントとウォッチポイント(設定・解除・一覧)、`bmsx_hunt op=end`、`bmsx_key` と `bmsx_type`、`bmsx_screen as=png`(`as=auto` の場合は PNG)、`bmsx_symbols`、`bmsx_reset`、`bmsx_run` の `how=pause` と `how=resume`、`bmsx_run_until`。
ステップ実行は `not_paused` で拒否されます。

実行中のページの状態によって決まる結果はすぐに変わる可能性があるため、実行中には返されません。
Z80 アドレス、セグメント、`ram:` に対する `bmsx_mem_resolve` は `not_paused` を返し、ページインしていないセグメントへの `bmsx_watch op=set` も同様です。
実行中のマシンで `at` にレジスタ(`pc`、`hl+2`)を指定すると、他の引数を検証したうえで同じ `not_paused` で拒否されます。
実行中のページの状態をもとに答える場合は、返答にその旨が示されます。
実行中に設定した VRAM のウォッチポイントは画面モードと照合されず、それで停止したときも、設定時の配置は通知されません。

## アドレスの形式

アドレスを受け取るツールは、いずれも以下の形式をサポートしています。

| 形式 | 意味 |
|---|---|
| `0xC000`、`$C000`、`#C000`、`C000h`、`49152`、`cpu:0xC000` | 現在 CPU から見えている Z80 アドレス。数字のみの場合は 10 進数として解釈されます。 |
| `pc`、`hl+2`、`sp` | レジスタが指す位置。マシンが一時停止している必要があります。 |
| `@DRAW_ENEMY`、`@DRAW_ENEMY+3` | 読み込んだシンボル。そのシンボルが属するセグメントを指します。 |
| `slot1.0:seg5+0x100` | スロット 1・サブスロット 0 のセグメント 5 の 0x100。ページインしていなくても指定可能です。 |
| `slot0.0+0x0100` | セグメントを報告しないスロットの Z80 アドレス 0x0100。そのスロットがその Z80 ページにページインしているときのみ読み取れます。 |
| `ram:seg12+0x1A30` | ページ 3(0xC000〜0xFFFF)のスロットにあるメモリマッパーの、セグメント 12 の 0x1A30。ページ 3 が別のスロットに切り替わっている場合は本体のメモリマッパーを使用し、メモリマッパーがない機種(MSX1 の多くなど)では使用できません。どのスロットを使用したかは返答に示されます。 |
| `vram:0x1B00` | VRAM。プログラムが VDP を通して使用するアドレス(R#14 とポート 0x98/0x99、または VDP コマンド)で指定します。SCREEN 7、8、10〜12 では VDP が 2 つの 64 kB バンクを交互に並べるため、vram:0x8001 はチップの 0x8001 番目のバイトではありませんが、ツールはあくまでプログラムから見たアドレスとして扱います。 |

セグメントは、利用者向け説明の「バンク」と同義です。
ツールが返すアドレスはすべて上記のいずれかの形式であるため、そのまま次の入力に流用できます。
同一セグメントが他の Z80 ページにもマップされている場合でも、Z80 アドレスは指定された Z80 ページ上のアドレスとして表示されます。

アドレス中の数字のみの数は 10 進数として扱われ、`4010` は 0x0FAA となります。
16 進数は `0x4010`、`$4010`、`#4010`、`4010h` と書きます。
シンボルファイルでは逆に、数字のみの場合は 16 進数です。
アドレスに数字のみの 4 桁以上の数を指定すると、返答の 1 行目にその解釈が示されます。
同じ数字を 16 進数として読んでも 0xFFFF 以下(`vram:` では 0x2FFFF 以下)であれば、16 進数での形式も併記されます。
アドレス以外の数の引数(個数、値、ポート)は、引用符の有無にかかわらず、`0x`(または `-0x`)で始まらなければ 10 進数です。
先頭が 0 でも 8 進数にはならず、アドレスとして大きすぎる数は拒否されます。
シンボルファイル中の 191 バイトより長い名前は、読み込み時に切り詰められます。

オフセットがセグメントの大きさを超えると後ろのセグメントへ続き、返答に実際の行き先が示されます。
スロットの最後のセグメントより後ろのセグメントは、他のセグメントに回り込ませずに拒否されます(`bmsx_mem_resolve` は情報として返します)。
セグメントを報告しないスロットに `seg<n>` を付けると、その旨を示す `bad_address` エラーとなります。
そのスロットがページインしている間に、Z80 アドレスで指定してください。

`ram:` はページ 3 に従い、それを使用した返答には、どのスロットをなぜ選択したかが示されます。
カートリッジのメモリマッパーも、BIOS がページ 3 をそこに切り替えていれば対象になります。
どちらもなければ `ram:` は拒否され、存在するメモリマッパーがスロットで示されます。
メモリマッパーのないマシンでは `0xC000` または `slotX.Y+0xC000` を使用します。
`bmsx_reg_write` の値を `ram:...` で指定したときも、同じ行が付きます。

`bmsx_mem_read`、`bmsx_mem_write`、`bmsx_undo` も同じ `vram:` アドレスを使用します。
取り消しは、画面モードが変わった後でも書き込んだ位置にバイトを戻し、その旨を示します。
VRAM が 64 kB の VDP で SCREEN 7 や 8 のときは、奇数の `vram:` アドレスには対応する VRAM がないため拒否されます(`out_of_range`)。
拡張 VRAM(vram:0x20000〜0x2FFFF、V9938 の MXC 拡張)は、どの画面モードでもチップの番号のままです。

`vram:` は常に VDP の VRAM です。
V9990(GFX9000、Video9000)には別の VRAM がありますが、ツールでは読み書きも、ウォッチポイントの設定も、検索もできません。

CPU がそのアドレスから読み取る値と、セグメントに格納されている値が異なる場合(SCC のレジスタやフラッシュのステータスなど)は、読み出しの返答でその旨を示し、格納されている値のセグメントアドレスを示します。

## ツールとエラー

| ツール | 補足 |
|---|---|
| `bmsx_status` | 8 kB マッパーでは、各 Z80 ページのセグメントを `seg3,seg5` のように前半・後半とも示します。一時停止中は、CPU が Z80 か R800(turbo R)か、画面モード(BASIC と同じ呼び方で `SCREEN 1`、`SCREEN 0 WIDTH 80` など。モードのビットが混在・未定義の場合はその旨)も示します。V9990(GFX9000、Video9000)があれば、一時停止中は V9990 の画面が表示されているか、そのモード、VDP の画面に重ねているか(スーパーインポーズ)も示します。vdp の行は V9990 ではなく VDP(V9938、V9958、TMS99x8)のものです。実行中は、代わりにマシン名と実行したフレーム数を示します。 |
| `bmsx_mem_resolve` | SCREEN 7、8、10〜12 で一時停止中の場合は、`vram:` アドレスに対応するチップのバイト番号も示します。デバッガのウィンドウの VRAM 表示でそのバイトがある位置です。 |
| `bmsx_stack` | 現在ページインしているセグメントで、戻りアドレスの直前で終わる命令が CALL、RST、HALT のいずれでもない段には、シンボルが誤っている可能性を示す印を付けます。 |
| `bmsx_dasm` | Z80 アドレスから始めると、Z80 から見えるとおりに読み進め、別のスロットやセグメントに変わる位置を示しながら 0xFFFF まで続けます。セグメントアドレスから始めると、そのセグメントの終わりで停止します。 |

「読み取りのみ」で使用可能なのは、読み取り用のツール(`bmsx_status`、`bmsx_slots`、バンクの一覧、`bmsx_mem_read`、`bmsx_mem_resolve`、`bmsx_stack`、`bmsx_dasm`、`bmsx_symbols`、`bmsx_hunt`、パスなしの `bmsx_screen`、ブレークポイントとウォッチポイントの一覧)と `bmsx_run how=pause` のみです。
それ以外には「書き込みも許可」が必要です。

エラーでは、問題のある引数が名指しされます。
ツールにない引数、必須の引数の省略、型の違う値、選択可能な値にない語は、サーバーがエラーコードなしで拒否し、エミュレータには何も送られません。
数の範囲はエミュレータが検証します(`out_of_range`)。
`arg_too_long` と `line_too_long`(呼び出し全体が 64 kB を超えた)のときは、何も実行されていません。

マシンとエミュレータに関するその他のエラー:

- `not_paused`: マシンの一時停止が必要です。一時停止するか、停止するまで実行させます。
- `no_machine`: エミュレータが停止中かリセット中です。`bmsx_run how=resume` ではマシンは起動しません。起動するのは `bmsx_reset how=hard` です。
- `busy`: 何も実行されていません。エミュレータが他の処理中か、メニューやダイアログが開いています。閉じてから再度呼び出します。
- `dialog_open`: `bmsx_reset` のみが返します。ダイアログやメニューが開いているか、ウィンドウの移動やサイズ変更の最中です。
- `read_only`: エージェント制御が「読み取りのみ」です。`revoked`: 「許可しない」に変更されました。

マシンがないときでも使用可能なのは、`bmsx_status`、ブレークポイントとウォッチポイントの一覧、シンボルの検索、`clear_all`、それに `op=list` が表示したアドレスでのウォッチポイントの解除です。
このとき、ブレークポイントを 1 つずつ解除することはできません。
設定済みのブレークポイントは保持され、マシンが起動すると改めて有効になるため、その時点で解除するか、`clear_all` を使用します。

クライアントが取り消した要求と、接続が閉じられた要求は、その時点で終了し、返答はありません。

## メモリの書き込みと取り消し

`bmsx_mem_write` で 1 回に書き込めるデータ量は、バイトの表現形式(`"3E 01 C9"`、`"0x3E, 0x01"`、`"3E01C9"` など)にかかわらず最大 511 バイトまでです。
これを超過すると `data` を名指しした `arg_too_long` エラーとなり、書き込みは一切行われません。
1 行の要求に収まらないデータは `line_too_long` で拒否されます。
RAM と VRAM への書き込み履歴は、直近 32 回分まで `bmsx_undo` で取り消すことができます。
ただし、リセットやスナップショットへの復帰を行うとこの履歴はクリアされます。

ROM、フラッシュ、マッパーのレジスタに対する書き込みはそれぞれのデバイスに直接送られ、その処理方法はデバイス依存となります(多くはバンク切り替えとして働き、元の値は読み出せません)。
結果は再読み込みによって確認する必要があり、これらの操作は `undo` で取り消すことはできません。
切り替え可能なマッパーのバンクレジスタへの書き込みは、エージェントによるバンク切り替え操作として扱われます(`bmsx_bank` を参照)。
セグメント境界を跨ぐ書き込みやレジスタの書き換えも取り消し不可です(`bmsx_reg_write` は変更前の値を返すため、手動で元に戻すことは可能です)。
取り消し処理は、その後にプログラム側で上書きされたバイトであっても、過去の古い値へと復元します。

## バンクの切り替え(bmsx_bank)

エージェントが切り替えたセグメントには、`bmsx_slots` と実行カードで `*` が付きます。
再開する前の戻し方は返答に示されます。
セグメント番号は ROM やフラッシュの先頭から数えたもので、Yamanooto のプログラムが設定したオフセットには左右されません。
`segment="sram"` を指定すると、SRAM 付きカートリッジの SRAM を割り当てます。
プログラムのどのバンク値でも選択できないセグメント(大きさが 2 のべき乗でない ASCII16 nf の ROM)は `out_of_range` で拒否されます。
プログラムが書き込む窓に SRAM を割り当てている間は、そこへのプログラムの書き込みは SRAM のファイルに入ります。

切り替えは `bmsx_undo` では元に戻りません。
切り替え中に取得したスナップショットでは、そのセグメントがプログラムの選択したものとして残ります。

## エミュレータの起動(--hidden、複数のインスタンス)

接続を受け付けているエミュレータがないと、どのツールも起動用のコマンドを返します。

- オプションは `--` の形で指定します。Git Bash は `/rom1` のような引数をパスに書き換えてしまいます。PowerShell では、引用符で囲んだプログラムのパスの前に `&` が必要です。これは PowerShell の呼び出し演算子で、バックグラウンド実行ではありません。バックグラウンドで起動するには、`Start-Process` または使用しているツールのバックグラウンド実行の機能を使用します。
- 起動したら、応答が返るまで(数秒)`bmsx_status` を呼び出します。その間に別のエミュレータを起動しないでください。
- パスは絶対パスで指定します。相対パスは、現在のディレクトリではなくエミュレータのフォルダを基準にします(`--rootdir`、`--machinedir`、`--inifile` は例外)。
- そのまま起動できるのは C-BIOS のマシン(`MSX - C-BIOS`、`MSX2 - C-BIOS` など)のみです。リリースには `MSX2.rom` などのシステム ROM が含まれていません。C-BIOS には BASIC がありません。ディスクのプログラムには、Nextor の入った `MSX2 - C-BIOS FDD` を使用します。BASIC や他のマシンを使用するには、ユーザー自身が用意した ROM ファイルを `Machines\Shared Roms` に配置する必要があります。
- `--listmachines` でマシンの一覧、`--listromtypes` で `--romtype1` に渡すマッパー名(`KONAMI GEN`、`SUPERPIERR`、`MEGAFLSHSCC+` のような短い形で、`bmsx_slots` が表示する名前とは異なります)、`--help` で他のオプションを確認できます。`--diskA`、ステートファイルから始める `--state`、`--speed`、マシンが起動したらすぐに一時停止する `--paused`、それに `--exitafter <frames>` と `--screenshot <file>` などです。`--exitafter` はウィンドウの × と同じ方法で終了し、終了コードは 0 です。ウィンドウのある起動でフォルダのディスクが変更されていると、終了前に確認を求めます。

起動したエミュレータは、`/F` を付けずに `taskkill /PID <pid>` で終了させます。
ウィンドウの × と同じ終了方法になり、SRAM が保存され、インスタンスファイルが削除されます。
ウィンドウのあるものは、フォルダのディスクが変更されていると先に確認を求めます。
pid は `Start-Process -PassThru` または `%LOCALAPPDATA%\blueMSXplus\agent\instance-<pid>.json` の名前から確認できます。

`--hidden` を付けると、ウィンドウ、音、ダイアログなしで動作します。
ツールは、スクリーンショットも含めて同じように使用できます。
`--agentcontrol full --hidden` で起動してください。
メニューがないため、後からエージェント制御を有効にすることはできません。
MCP クライアントが終了しても動作し続けます。
`taskkill` で終了させたとき、フォルダのディスクは書き戻しのオプション(`--diskAwriteback` など)を付けたもののみが書き戻されます。
`--hidden` のエミュレータは、最初の起動でマシンを起動できないと終了コード 2 で終了します。
それより後(ハードリセットなど)に起動できなかったときは、標準エラーに報告し、マシンなしで動作し続けます。

複数のエミュレータが接続を受け付けていると、返答にそれぞれの pid と最後に起動したマシンが示され、どうすればよいかが示されます。
MCP クライアントの設定で `--instance` を指定すると、1 つに固定できます。
大文字と小文字は区別されません。
マシン名に完全に一致するものが優先されます。
完全一致がない場合、名前の一部が 1 つにのみ一致すればそれが使用され、複数に一致する場合は一覧を添えて拒否されます。
数字のみの値は pid(またはその数字そのものが名前のマシン)とみなされます。
pid はエミュレータを起動し直すと一致しなくなりますが、同じマシンを動作させている 2 つを区別できるのは pid のみで、マシンをまだ起動していない行に当てはまるのも pid のみです。
エージェント制御が「許可しない」のエミュレータは一覧に表示されません。

## キー名

`bmsx_key` で使用可能な名前です。
`ctrl+stop` のように `+` でつなぐと同時に押します。

- ファンクション・編集: `f1`〜`f5` `stop` `cls` `select` `ins` `del` `esc` `backspace` `tab` `return` `space` `pause` `print`
- 修飾キー: `ctrl` `leftshift` `rightshift` `caps` `graph` `code` `torikeshi` `jikkou`
- 英字・数字: `a`〜`z` `0`〜`9`
- 記号: `neg` `circomflex` `backslash` `at` `leftbracket` `rightbracket` `semicolon` `colon` `comma` `period` `div` `underscore`
- カーソル: `left` `up` `down` `right`
- テンキー: `num0`〜`num9` `numdiv` `nummul` `numsub` `numadd` `numperiod` `numcomma`
- ジョイスティック: `joy1-up` `joy1-down` `joy1-left` `joy1-right` `joy1-button1`〜`joy1-button6`、2 番は `joy2-` で同様

未知の名前を指定すると、使用可能な名前の一覧を添えて拒否されます。

## シンボルの紐付け(セグメントごとのシンボル)

シンボルは、スロット、サブスロット、セグメント、アドレスの組で管理されます。
バンク番号(SLD ではページ番号)のあるファイルは、1 つのスロットに紐付けます。
紐付くのは、`slot` 引数で指定したときか、ファイル名が ROM と一致し、その ROM のセグメント数が足りるときです。
どの Z80 ページにもファイルのページが 1 つずつしかない SLD ファイルは、バンクのないプログラムとして読み込まれ、読み込み時にその旨が通知されます。
それ以外では紐付けず、そのファイルのシンボルは表示にも `@名前` での指定にも使用されません。
返答に候補のスロットが示されるため、`slot="1.0"` のようにそのいずれかを指定して再度読み込みます。
セグメントがファイルのページより大きく、アセンブルしたアドレスに決して現れないページが出るスロットには紐付けず、候補にも示しません。
セグメントを報告しないスロットには紐付けません。
その ROM と同名のファイルも紐付かないままで、そのスロットを `slot=` で指定すると拒否されます。
大きさのみで紐付けることはしません。
カートリッジを差し替えると、状態表示がその旨を示します。
ページ 3 は RAM であるため、0xC000 以上のシンボルは ROM には紐付けません。

バンクのあるファイルをメモリマッパーに紐付けると、バンク番号をマッパーのセグメント番号として読みます。
16 kB セグメントに 8 kB の SLD ページを載せる場合は、ページ n をセグメント n/2 として読みます。
実行中に MSX-DOS 2 や Nextor からセグメントを受け取るプログラムは、多くの場合別の番号を割り当てられ、そのときシンボルは違うセグメントを指します。
読み込み時にその旨が通知されます。

フォルダと拡張子を除いた名前が読み込み済みのファイルと一致する場合は、読み込み済みのファイルは新しいファイルで置き換えられます。
スロットなしで読み込んだファイルのシンボルは、ページインしているスロットに紐付いたファイルがないときのみ使用され、0xC000 以上では常に使用されます。
複数のファイルにある同じ定義は 1 つとして扱い、複数のファイルを読み込んでいるときは、検索結果にどのファイルの名前かを添えます。
逆アセンブルでは、バンクのある Z80 ページへの呼び出し先には、そのアドレスを定義するセグメントが 1 つのみのときに名前を付けます。
セグメント内の相対ジャンプの飛び先は、その位置のシンボルで示し、シンボルがなくセグメントもページインしていなければセグメントアドレスで示します。

## 値の検索(hunt): 変数を探す

```
bmsx_hunt       op=start   width=u8
bmsx_run_until  timeout_ms=3000 pause_at_timeout=true
   ... または再開して、値が変わったら一時停止する ...
bmsx_hunt       op=refine  compare=decreased
```

`start`、`refine`、`list` にはマシンの一時停止が必要で、絞り込みの合間にはマシンを動作させる必要があります。
「読み取りのみ」ではユーザーが再開操作を行う必要があります。
検索範囲は、スロットが報告するすべての RAM(メモリマッパー、通常の RAM、SCC-I カートリッジの RAM)と VRAM で、バッテリーバックアップの SRAM、MegaRAM、フラッシュは含みません。
幅の広い検索はすべてのバイト位置を調べるため、X にある 2 バイトの値は、正確な値で絞り込むまで X-1 にも現れます。
比較に渡す値(`eq`、`lt`、`in_range` など)は幅に収まる必要があります(`u8` の場合は 0〜255、`s8` の場合は -128〜127 など)。
リセットやスナップショットへの復帰で検索は終了します。

VRAM は、検索を始めたときの VDP の配置で検索します。
検索中に画面モードが変わって配置が変わったときは、一覧にその旨が示されます。
VRAM が 64 kB の VDP で SCREEN 7 や 8 のときは、VRAM を検索の対象から外します。

## ウォッチポイント: バイトを書き換えた箇所を特定する

```
bmsx_watch      at="@lives"
bmsx_run_until  timeout_ms=10000
bmsx_status
```

I/O ポートは `port=152` または `port="0x98"` で指定し、`at` とは同時に使用できません。
停止はウォッチポイントによるものとして、書き込まれたアドレスと一緒に通知され、PC は書き込んだ命令の次を指しています。
アドレスは CPU から見えている必要があります。
ページインしていないセグメントには、セグメントアドレスで `bmsx_break` を使用します。
メモリのウォッチポイントは Z80 アドレスを監視します。
ページインしているセグメントのアドレスで指定すると、そのセグメントが現在見えている Z80 アドレスに設定され、後で別のセグメントがページインしても、そこへの書き込みで停止します。
1 つのアドレスに設定できるウォッチポイントは 1 つのみで、同じアドレスに再設定すると前のウォッチポイントが置き換えられます。
`value` は比較する条件のときのみ使用します。
ソケットから設定できるウォッチポイントは 64 個までです。
ウォッチポイントは解除するまで残ります。

VRAM のウォッチポイントは、書き込みのたびに、その時点の VDP の配置でのアドレスを参照します。
プログラムが SCREEN 0〜6 の配置と SCREEN 7/8/10〜12 の配置の間で画面モードを切り替えると、同じ `vram:` アドレスが別のバイトを指します。
そのとき停止すると、ウォッチポイントを設定したのは別の配置のときだと通知されます。
SCREEN 7、8、10〜12 で停止したときは、デバッガのウィンドウが示すチップのバイト番号も通知されます。
プラグインとデバッガのウィンドウのウォッチポイントは、チップのバイト番号のままです。
画面モードの切り替え前に始まった VDP コマンドは、始めたときの配置のまま続き、その書き込みは現在の VDP の配置で通知されます。
VRAM が 64 kB の VDP で SCREEN 7 や 8 のときは、奇数アドレスへのウォッチポイントは拒否されます(対応する VRAM がないため)。
このとき VDP コマンドは vram:0x10000 以降にも書き込めますが、ツールはそこを範囲外として拒否するため、その書き込みは読み取ることも、ウォッチポイントを設定することもできません。

## ブレークポイント: 別のバンク、ページインしていないコード、解除される条件

```
bmsx_break      at=slot1.0:seg5+0x0100
bmsx_run_until  timeout_ms=10000
```

セグメントのブレークポイントは、そのセグメントがどの Z80 ページにページインしていても停止します(8 kB マッパーでは 1 つのセグメントが 2 つの Z80 ページに見えることがあり、どちらのアドレスで設定しても同じブレークポイントです)。
セグメントのブレークポイントは 64 個まで設定できます。
HALT 命令に設定したブレークポイントは、CPU がそこに着くたびに 1 回停止します。

サーバーの強制終了、5 秒を超える切断、「許可しない」によって通常のブレークポイントが解除されたときは、次に再接続した呼び出しがその数を通知します。
通知する先は、戻ってきた同じサーバーと、最初に接続した他のクライアント(1 回のみ)です。
正常に終了した場合は、通知なしに解除されます。

`clear_all` は、MCP 経由で設定したブレークポイントをすべて解除します。
デバッガのウィンドウで設定したものは残り、MCP からは解除できません。
それを解除しようとしたときや、設定されていないものを解除しようとしたときは `not_set` を返します。
`op=list` にはウィンドウで設定したものも表示されますが、MCP 経由で設定したものは、デバッガのウィンドウには表示されません。
マシンを起動し直す前から残っているセグメントのブレークポイントが、現在はセグメントを報告しないスロットを指している場合は、`clear_all` でしか解除できません。

## 実行とステップ実行(run_until、step)

`run_until` は新しい停止を待ちます。
呼び出す前に起きてまだ通知していない停止(`resume` の返答中に起きた停止など)や、新しいセッションの開始時にマシンがすでに停止していた場合のその停止は、「this stop happened before the call」と添えて 1 回のみ通知されます。
停止の理由は `breakpoint`、`watchpoint`、`step`、`user`(一時停止)、`step_back`(デバッガの、1 命令前に戻るステップ実行が終わった)、`vram_timing`(デバッガの VRAM アクセス検査。MSX1 の VDP のみ)、`frame`(エミュレータが、画面に出ている映像のフレームで自ら一時停止した: コマ送りが終わった、1 フレーム戻す・前の画面更新まで戻す操作が終わった、またはそれ以上戻れなかった、一時停止から始めた押している間の巻き戻し・最高速度を離した、またはその巻き戻しが保持している最も古い時点に着いた)、`machine`(停止、リセット、入れ替え)です。

エミュレータが画面の表示に同期しているときは、1 ステップごとに次のフレームを待つため、ステップ数が多いと、ブレークポイントと `run_until` を使用するより遅くなります。
ウォッチポイントで停止した直後の最初のステップは、途中だった命令を終えるのみの場合があり、そのときはその旨が通知されます。
`step_out` は、CPU が記録した戻りアドレスがスタックにないとき(メインループの最上位など)は拒否されます。
`step_over` と `step_out` の終わりは、ステップとして通知されます。
「読み取りのみ」への変更は新しい要求から有効になり、実行中のステップの繰り返しはすぐに終了します。

## リセット、スナップショット、フラッシュ

`bmsx_reset` は、ハードでもソフトでもブレークポイントとシンボルを残し、値の検索を終了し、書き込みの取り消し履歴を消去します。
電源を切った後に起動できなかった場合(`not_started`)は、ハードリセットが成功するまでマシンは動作しません。

ハードリセットの返答には、新しく再読み込みしなかったものが示されます。

- MSX が書き込んだディスクのフォルダと、ハードディスクのフォルダは、そのまま残ります。エミュレータで取り出して再挿入すると再読み込みします。
- フラッシュカートリッジは、書き込んだ内容を blueMSX+ の `SRAM` フォルダに保存します。Yamanooto、ASCII16-X、Flash-ROM SCC は `<rom>.flash`(またはフラッシュと同じ大きさの `<rom>.sram` 全体)を ROM に重ね、Mega Flash Rom SCC 系(SCC、SCC+、Manbow 2、Hamaraja Night)は `<rom>.sram` 全体から始めます。返答はそのファイルを名指しします。ROM のみから始めるには、マシンが動作していないとき(エミュレータのメニューの **実行 → 停止** の後、または終了した後)にそのファイルを削除してから、マシンを起動し直します。これを通知するのはハードリセットのみです。作り直した ROM で新しく起動したエミュレータは何も通知せずにそのファイルを使用するため、先にそのフォルダを確認します。こうしたカートリッジは、ROM ファイルではなくフラッシュの大きさ(ASCII16-X の場合は 8192 kB)を示します。
- 読み込んだ後にディスク上で変更されたシンボルファイル、またはシンボルより後に書き込まれた ROM。シンボルを再度読み込みます。
- セグメントのブレークポイントは同じセグメントとオフセットに残ります。新しいシンボルと照らし合わせてください。

`bmsx_snapshot` には一時停止中のマシンが必要で、復帰した後もマシンは一時停止したままです。
ソフトリセットではスナップショットは消えません。
ファイルには保存できないため、ステートファイルを使用する場合は起動時に `--state` を指定します。

- 取得した後に DOS がディスクイメージへ書き込んでいると、RAM 上の FAT は戻るのにイメージは戻らないため、そのディスクに再び書き込む前にリセットします。
- ブレークポイントとウォッチポイントはそのまま残ります。エミュレータ自身の巻き戻しで戻れるのは、復帰より後の時点のみです。復帰した後は、フレームが進むまでウィンドウと `as=png` は前の画像のままですが、`as=text` は最新です。エミュレータ自身の巻き戻しと同じく、いくつかの装置のタイマーはすぐには動き出しません。turbo R の PCM 音源、シリアル、MIDI、ネットワークの入力、ColecoVision のスピナーなどです。
- 復帰した PC にブレークポイントがある場合: 一時停止中に復帰すると、次の `run_until` はすぐそこで停止します。ブレークポイント(またはステップオーバーやステップアウトの終わり)で停止しているときに復帰すると、次の `run_until` はそこを通過します。HALT の中に復帰すると、CPU が再びそこに着いたときに停止します。
- ダイアログやメニューが開いているときは、取得も復帰も `busy` で拒否されます。

## 文字の入力(bmsx_type)、キー入力と画面(PNG、スクリーンショット)

`bmsx_key` は、キーボードを直接読み取るゲームのために、`bmsx_type` の下限である 4 フレームより短い押下も受け付けます。

1 回で入力できる量を超える文章は、何も入力されずに拒否されます。
すべてのキーが入る前にマシンが停止すると `input_interrupted` を返します。
一時停止やブレークポイントのときは、残りは再開したときに入るため、再送しないでください。
返答はキーがキーボードに届いたことを表すのみで、プログラムが読み取ったことまでは表しません。

`bmsx_screen` は、テキストモード(SCREEN 0、SCREEN 0 WIDTH 80、SCREEN 1。212 ライン時の 27 行を含む)ではテキストを返し、グラフィックモードのときやパスを指定したときは PNG を書き出してそのパスを返します。
実行中は `as=text` は `not_paused` です。
パスは Windows の絶対パス(`C:\...` または `\\server\...`)で指定し、`/c/...` は拒否されます。
テキストはプログラムが書き込んだ文字コードで、描かれている形ではないため、独自フォントを使用するプログラムでも文字コードのまま読み取れます。
0x20〜0x7E 以外のコードは `.` で示し、番号を示します。
文字のパターンが消されている、文字色と背景色が同じ色で描かれる(SCREEN 1 では文字ごとにカラーテーブルの値で判断します)、表示がオフ、画面がスクロールしている、混在モードである、のいずれかに当たるときは返答に注記が付くため、PNG で確認します。

V9990(GFX9000、Video9000)の画面が表示されている間は、V9990 の画面には読み取れるテキストがないため、`as=auto` は PNG を返します。
`as=text` はそれでも VDP のテキストを返し、1 行目で V9990 の画面がその上に重なっている、または代わりに表示されていることを示します。
どちらの画面が表示されているかは `bmsx_status` が示します。

エージェント制御が有効な場合は、最小化したエミュレータも描画を続け、`--hidden` でも描画するため、PNG は最新です。
「許可しない」のときに最小化したウィンドウでは、PNG は `not_drawing` で拒否され、返答に対処が示されます。

## 通信プロトコル

サーバーは変換するのみで、処理はエミュレータが行います。
他のプログラムも同じソケットを使用できます。
127.0.0.1 上で 1 行に 1 つの JSON をやり取りする形式で、ポート番号とトークンは以下のファイルにあります。

```
%LOCALAPPDATA%\blueMSXplus\agent\instance-<pid>.json
```

接続したら 2 秒以内に `{"op":"hello","token":"...","owner":N}` を送ります(間に合わないとエミュレータが接続を閉じます)。
次に `{"op":"help"}` で操作の一覧を取得します。
`owner` は、クライアントが動作している間ずっと同じ値を使用する正の数です。
`owner` のない hello や、別のクライアントの `owner` を持つ hello は、前のクライアントが残した通常のブレークポイントを解除します。
そのため、エージェントの呼び出しの合間にスクリプトが接続すると、エージェントの通常のブレークポイントが通知なしに解除されます。
一度に応対するクライアントは 1 つのみで、2 つ目の接続は最初の接続が閉じるまで返答なしで待たされます。
もう再接続しないクライアントは、閉じる前に `{"op":"session.end"}` を送ると、設定した通常のブレークポイントがすぐに解除されます。

1 行の要求は 65535 バイトまでです。
JSON の型が違う値には `bad_arg` を返します。
`null` は引数を省いたのと同じで、操作が読まないキーは無視します。

返答の文は MCP のツール名で書かれています(「pause it first (bmsx_run how=pause)」など)。
ソケットでは、各ツールが操作に対応します。
`bmsx_run` は `run`、`bmsx_break op=set` は `bp.set`、`bmsx_bank` は `bank.list` または `bank.set` といった具合で、`help` で一覧を取得できます。
